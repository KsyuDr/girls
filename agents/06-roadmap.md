# Этапы разработки бэкенда

Модель — инкрементная (ЛР3): каждый этап — законченный кусок, который работает и проверен.

## Критерии готовности этапа (Definition of Done)
1. Код + миграция Alembic (если менялась схема).
2. Автотесты pytest на новый функционал: успешные сценарии + ошибки (401/403/404/409/422).
3. `ruff check`, `ruff format --check`, `eslint`, `prettier --check` — без ошибок (pre-commit).
4. Ручная проверка в браузере (встроенный браузер или Helium MCP): Swagger `/docs`,
   после интеграции — живой фронт.
5. Обновлены `agents/` (статус здесь + решения/контракт, если менялись).
6. Коммит(ы) в формате Conventional Commits.
